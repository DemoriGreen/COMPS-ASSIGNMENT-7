I used a stack for the undo and redo system because the most recent action should be the first one that gets undone. For example, if I add one item and then add another item, I would expect the second item to be removed first. I used one stack to keep track of actions that can be undone and another stack for actions that can be redone. When a new action is performed, it is added to the undo stack, and the redo stack is cleared because the old redo actions are no longer useful.

I used a queue for the help desk because customers should be helped in the same order that they arrive. The customer who has been waiting the longest should be helped first. New customers are added to the back of the line, while customers are removed from the front. I also made sure that the front and rear are reset when there are no customers left in the queue.

My classes are different from using Python lists because I created the data structures myself with Node objects. Instead of relying on list methods such as append or pop, each node stores a value and a reference to the next node. This helped me understand how the structures work behind the scenes. It also required me to handle things like empty stacks and queues and make sure the front, rear, and top references were updated correctly.
